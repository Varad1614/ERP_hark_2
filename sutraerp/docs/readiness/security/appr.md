Residual notes: requests raised by background work (or by code paths that bypass the web
`authenticate` middleware, e.g. test routers layering an `AuthContext` directly) record
`requested_by = NULL` (no human maker); their decisions still need an identified human checker, and
the money decisions additionally read makers from status history / maker columns. Every production
request passes `authenticate`, which sets the requester. The ledger keys on the business-key
subject; handlers whose subject differs from the path id use `guard_decision_for_row`.
